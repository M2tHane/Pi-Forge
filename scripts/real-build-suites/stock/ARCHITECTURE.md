# 小仓库进销存 技术栈

## 1. 后端

- Node.js 22.13 及以上（本机是 24），ES 模块（`package.json` 里 `"type": "module"`），纯 JavaScript，不用 TypeScript。
- HTTP 用 `node:http` 自己写路由，不用 Web 框架。
- **运行时只用 Node 自带模块**（`node:http`、`node:sqlite`、`node:fs`、`node:crypto` 等），`dependencies` 为空；开发依赖也尽量不用，要用时写进 `devDependencies` 并提交 `package-lock.json`。
- 目录与分层由架构师定（写进 docs/arch/overview.md）。

## 2. 数据库

- SQLite，用 Node 自带的 `node:sqlite`（`DatabaseSync`），一个文件放在 `DATA_DIR` 下（PRD 的 REQ-001）。
- 表结构在服务启动时自动建好或升级到最新版本，不需要单独执行迁移命令；建表语句提交进仓库。
- 一张单据造成的全部库存变化、流水与状态修改放在一个事务里（PRD 的 REQ-008 AC5）。
- 金额（分）与数量都用整数列。

## 3. 前端

- 原生 HTML、CSS、JavaScript（浏览器原生 ES 模块），**不用框架、不需要构建步骤**，由同一个 Node 进程托管静态文件；PRD 页面表里的每个路径都直接返回 HTML（REQ-016 AC1）。
- 样式照 `docs/prototype/` 的 `DESIGN.md` 与 `theme.css`：前端基础把这两个文件拷进产品，照它们写公共组件（顶栏、导航、表格、对话框、提示、金额格式化）。
- 调用接口统一经过一个请求函数：带上登录令牌，收到 401 清掉令牌跳到登录页。令牌存在浏览器的 `localStorage`。
- 不用第三方前端库。

## 4. 测试与检查

- 测试工具用 Node 自带的 `node:test` 与 `node:assert`，`npm test` 运行全部测试。
- 接口测试与验收测试：测试自己启动服务（子进程或同进程），**每次测试运行用自己的临时数据目录**（`fs.mkdtemp`）**和空闲端口**（监听 0 号端口或用程序分配的端口）：几个任务在各自的工作区里同时跑测试，不能互相干扰；测试结束停掉服务、删掉临时目录。
- 验收测试按 PRD 的 `REQ-xxx.ACn` 逐条调用 HTTP 接口，不开浏览器；页面的验收测试只检查页面路径返回 HTML，页面由每批的浏览器验收检查。
- 前端的纯逻辑（元与分的换算、金额格式化、表单校验）写成不依赖 DOM 的模块，用 `node:test` 测。
- lint：不用。架构检查、契约比对由架构师定（写成项目里的 Node 脚本，不引入第三方工具）。

## 5. 运行与部署

- 一台机器上一个 Node 进程同时提供接口和静态文件：`npm start`，端口与数据目录见 PRD 的 REQ-001。
- 不用 Docker；不需要数据库服务、缓存、消息队列和外部服务。
- `npm install` 之后直接能跑，不需要别的安装步骤。

## 6. 必须用与不能用的

- 不能用第三方运行时依赖（见第 1 节）。
- 密码用 `node:crypto` 的 scrypt 加随机盐存散列，响应里永远不带（PRD 的 REQ-003 AC2）。
- 登录令牌用 `node:crypto` 生成随机字符串，存在数据库里：重启后仍然有效，退出、停用后立即失效（PRD 的 REQ-002、REQ-003 AC5）。
- 时间一律按 UTC 存与比较（PRD 的通用约定）。
